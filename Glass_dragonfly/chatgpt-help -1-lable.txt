Now we know exactly why it failed.

getLabelization in Dragonfly is not:

label_ch.getLabelization(0, 0, 0, nx-1, ny-1, nz-1)

It actually requires 13 arguments:

getLabelization(
    minX, minY, minZ,
    maxX, maxY, maxZ,
    iTIndex,
    min, max,
    considerDiagonal,
    IProgress,
    pInVolumeROI,
    pOutData
)

The Dragonfly docs say it labels adjacent voxels and returns a MultiROI; if you pass an output MultiROI, it writes into it, otherwise it creates a new one.

And getAsMultiROI is also not zero-argument. Its signature is:

getAsMultiROI(inOutStructuredGrid, IProgress)

It converts a structured grid to a MultiROI, and if the source is a channel, the output MultiROI will contain a label for every non-zero channel value.

So your script failed because it only passed the bounding box. After that failure, your own fallback path renamed the temporary label channel to Glass_Beads_Labeled, which is why you ended up with a channel instead of a real MultiROI. The docs also confirm publish() is what makes an object show up in the Dragonfly UI.

What Claude should change

The cleanest next try is actually getAsMultiROI(None, None) first, because your labeled channel already contains bead IDs 1…282, and the docs say a channel source becomes a MultiROI with one label for every non-zero channel value.

If that fails in your binding, then use the full getLabelization(...) call.
